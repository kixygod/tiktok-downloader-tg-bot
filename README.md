# TikTok Telegram Bot

Быстрый и эффективный Telegram бот для скачивания видео с поддержкой Hysteria2 VPN, веб-дашбордом статистики и умным сжатием видео.

## 🚀 Особенности

- **Асинхронная обработка** через Redis очередь (BullMQ)
- **Hysteria2 VPN поддержка** - весь трафик только через VPN (sing-box)
- **Умное сжатие** - автоматическое сжатие видео под лимит 50MB
- **Веб-дашборд** - статистика за день/неделю/месяц/всё время с графиками
- **Высокая производительность** - TypeScript + Node.js 20
- **Безопасность** - все файлы временные, автоматическая очистка
- **Масштабируемость** - легко добавить больше воркеров
- **Умные уведомления** - показывает среднее время ожидания
- **Мультиплатформенность** - TikTok, YouTube Shorts, VK Clips, Instagram (Reels и посты), X/Twitter (посты `/status/…`, ссылки `t.co`)
- **Пакетная загрузка** - несколько ссылок в одном сообщении
- **Rate limiting** - защита от злоупотреблений
- **Deduplication** - не добавляет дубликаты в очередь
- **Прогресс загрузки** - отображение процента загрузки в реальном времени
- **Redis persistence** - сохранение кэша и rate limit при перезапуске

## 📋 Требования

- Docker и Docker Compose
- Hysteria2 сервер с доступом в интернет
- Telegram Bot Token (получить у @BotFather)

### 3. Настройка Hysteria2

**⚠️ ВАЖНО**: Файл `xray/config.json` содержит ваши приватные ключи и НЕ должен попадать в Git!

1. **Скопируйте пример конфигурации**:
   ```bash
   cp xray/config.example.json xray/config.json
   ```

2. **Отредактируйте `xray/config.json`** с вашими данными Hysteria2:

```json
{
  "log": {
    "level": "warn"
  },
  "inbounds": [
    {
      "type": "socks",
      "tag": "socks-in",
      "listen": "0.0.0.0",
      "listen_port": 1080,
      "sniff": true,
      "sniff_override_destination": false
    },
    {
      "type": "http",
      "tag": "http-in",
      "listen": "0.0.0.0",
      "listen_port": 1087,
      "sniff": true,
      "sniff_override_destination": false
    }
  ],
  "outbounds": [
    {
      "type": "hysteria2",
      "tag": "hysteria2-out",
      "server": "YOUR_SERVER_IP",
      "server_port": 443,
      "password": "YOUR_PASSWORD",
      "tls": {
        "enabled": true,
        "server_name": "YOUR_SNI",
        "insecure": false
      },
      "obfs": {
        "type": "salamander",
        "password": "YOUR_OBFS_PASSWORD"
      }
    },
    {
      "type": "direct",
      "tag": "direct"
    }
  ],
  "route": {
    "rules": [
      {
        "network": "tcp,udp",
        "outbound": "hysteria2-out"
      }
    ],
    "final": "hysteria2-out"
  },
  "dns": {
    "servers": [
      {
        "tag": "google",
        "address": "https://8.8.8.8/dns-query",
        "detour": "direct"
      },
      {
        "tag": "cloudflare",
        "address": "https://1.1.1.1/dns-query",
        "detour": "direct"
      }
    ],
    "strategy": "prefer_ipv4"
  }
}
```

**Параметры для замены:**
- `YOUR_SERVER_IP` - IP адрес вашего Hysteria2 сервера
- `YOUR_PASSWORD` - пароль из Hysteria2 конфигурации
- `YOUR_SNI` - Server Name Indication (обычно домен сервера)
- `YOUR_OBFS_PASSWORD` - пароль для обфускации (salamander)

## 🆘 Решение проблем

### Бот не отвечает
1. Проверьте `BOT_TOKEN` в `.env`
2. Убедитесь что бот запущен: `docker compose logs bot`
3. Проверьте настройки бота в @BotFather:
   ```
   /setprivacy - Disable (чтобы видеть все сообщения)
   /setjoingroups - Enable (для работы в группах)
   ```

### Ошибки скачивания
1. Проверьте настройки Hysteria2 в `xray/config.json`
2. Убедитесь что VPN сервер работает
3. Проверьте логи воркера: `docker compose logs worker`
4. Проверьте логи прокси: `docker compose logs xray`

### Дашборд недоступен
1. Проверьте что порт 3000 открыт
2. Проверьте `DASHBOARD_BASIC_AUTH` в `.env`
3. Проверьте логи бота: `docker compose logs bot`

### Файлы слишком большие
1. Бот автоматически сжимает видео под 50MB
2. Если не получается - отправляет сообщение об ошибке
3. Настройте `SIZE_LIMIT_MB` в `.env` (по умолчанию 50)


**Примечание**: Прокси настраивается автоматически через переменные окружения в `docker-compose.yml`:
- `HTTP_PROXY=http://xray:1087` - HTTP прокси для yt-dlp
- `HTTPS_PROXY=http://xray:1087` - HTTPS прокси
- `ALL_PROXY=socks5h://xray:1080` - SOCKS5 прокси (fallback)

### Docker Compose
- **Redis**: очередь задач с AOF (persistence)
- **xray** (sing-box): Hysteria2 клиент с HTTP (1087) и SOCKS5 (1080) прокси
- **Bot**: основной сервис с дашбордом (порт 53500)
- **Worker**: обработка видео через VPN (yt-dlp, ffmpeg)
- **Логи контейнеров**: `max-size: 2m`, `max-file: 2` на сервис (см. `x-logging` в `docker-compose.yml`)

### Мало места на диске (маленький VPS)
- **`JOBS_RETENTION_DAYS`** (по умолчанию 10) — полное удаление строк `jobs` старше N дней; очистка каждые **`JOBS_PURGE_INTERVAL_HOURS`** (по умолчанию 6).
- **`REDIS_KEY_TTL_SEC`** (по умолчанию 1800 = 30 мин) — кэш чатов/аватаров в Redis у бота.
- **`REDIS_EXPAND_URL_TTL_SEC`** у воркера (по умолчанию **86400** = 24 ч) — сколько живёт соответствие «URL из сообщения → URL после редиректа» для поиска файлов кэша; должно быть не меньше срока файлового кэша (~24 ч).
- В дашборде у строк без кэша кнопка **↻** вызывает `POST /api/admin/cache/rehydrate/:jobId` — восстанавливает запись в Redis, если файл ещё есть на диске (без повторной отправки ссылки в чат).
- После первого массового DELETE PostgreSQL может освободить место не сразу; при необходимости на хосте: `docker compose exec postgres vacuumdb -U bot -d tiktok_bot --analyze` (или дождаться autovacuum).
- Старые образы Docker: `docker image prune -a`

## Устойчивость обработки и журнал

- `PROCESS_TIMEOUT_MS` (по умолчанию 180000) ограничивает отдельный запуск yt-dlp/ffmpeg. По истечении времени завершается вся группа дочерних процессов. Curl проверяет HTTP-ошибки и ограничивает время соединения/загрузки.
- Временные файлы каждого задания лежат отдельно и удаляются в `finally`. Каталоги заданий, оставшиеся после аварийного завершения, очищаются через 24 часа. Неполный альбом или ошибка отправки в Telegram считается ошибкой задания.
- При временном отказе бот показывает сообщение о повторе. Окончательная ошибка появляется после последней попытки. Требование входа от yt-dlp не отменяет повтор, если резервные публичные загрузчики тоже временно отказали. Явно приватные или удалённые публикации не повторяются.
- Журнал этапов находится в постоянном томе: `/tmp/downloads/journal/events.jsonl`. Ротация: текущий файл и 3 архива примерно по 2 MiB. Это ограниченный журнал последних событий, а не бессрочный архив. Токены Telegram и пароли в URL скрываются.
- Статистика сначала сохраняется в `/tmp/downloads/stats-outbox`, затем отправляется боту. При недоступности бота/БД файлы остаются для повторной доставки каждые 30 секунд и после перезапуска. Пока доставка недоступна, outbox растёт; свободное место нужно контролировать. `event_id` предотвращает дубли при повторной доставке одной записи. Таблица `jobs` сохраняет существующий срок хранения.
- Короткие ссылки TikTok на один пост используют общий канонический URL без параметров отслеживания, поэтому не создают разные записи файлового кэша.

### Публикации, требующие входа

До необходимости cookies используются публичные резервные методы: TikTok embed для фото, Tikwm, Tikmate и SSSTik. Tikmate получает полный URL через POST-форму `/api/lookup`, затем строится MP4-ссылка из строкового `id` и `token`. SSSTik получает гостевой токен формы со страницы и отправляет POST `/abc?url=dl`, без cookie и входа в аккаунт. Он поддерживает видео и фото, но зависит от HTML-разметки и доступности сервиса; пустые ответы и HTTP-ошибки сохраняются в журнале. Успешный выбор резервного сервиса также журналируется. WebP-фото преобразуются в JPEG перед отправкой в Telegram. Приватные публикации эти сервисы не открывают.

Для тестов преобразования изображений нужны локальные `ffmpeg` и `ffprobe` (в Docker worker они уже установлены).

Можно сохранить Netscape cookies в `worker/cookies/tiktok.txt` и задать `YTDLP_COOKIES_FILE=/app/cookies/tiktok.txt`. Файл исключён из Git и подключается только для чтения. Контейнер работает под UID 1001: файл должен быть доступен этому пользователю; например, владелец UID 1001 и права 600. Воркер создаёт отдельную рабочую копию cookies для каждого задания и удаляет её вместе с временными файлами. Не храните cookies в чатах или журнале. Cookies могут истечь, а ограничения источника могут сохраняться даже с ними.

После обновления нужно пересобрать **bot и worker** вместе: bot добавляет nullable-колонку `event_id` и уникальный индекс к существующей таблице, не удаляя старые записи. Обычная пересборка Docker может использовать старый слой установки yt-dlp; для обновления загрузчика используйте пересборку worker с `--no-cache`. Автоматического изменения running-кода или самообновления загрузчика нет.

Docker-образы собираются в два этапа: TypeScript, компиляторы и devDependencies остаются в builder. Runtime-образы содержат только собранный код и необходимые зависимости.
